# 0.5.0 — DSH `0.2` line

Release notes for `dsh-edit-approval@0.5.0`.

---

## Compatibility — read this first

| | |
| --- | --- |
| **Supported DSH range** | **the `0.2` line** — `>=0.2.0-rc.1 <0.3.0` |
| Verified against | `@deepseek-ai/*@0.2.2-rc.2`, the version `devDependencies` pin exactly |
| Declared as | the same bounded `^0.2.0-rc.1`, in every `@deepseek-ai/dsh-*` peer **and** in `engines.dsh` |
| Previous line | `0.1.7` — **dropped**, refused at startup with a diagnostic |
| cordis / schemastery | `^4.1.0` / `^3.19.0` |
| Node.js | `^22.19.0 \|\| >=24.0.0` |

Every published `0.2.x` release is admitted, including prereleases; `0.1.7-rc.2`
and `0.3.0-rc.1` are refused. Both ends were measured by calling the harness's
own `evaluatePluginCompatibility`, not inferred from the range.

**`engines.dsh` must keep its `^`.** From DSH 0.2.2 the admission gate reads an
own `engines.dsh` and *ignores every peer*, so a bare `>=` floor there would
silently admit `0.3.0` and everything above it. This release fixes exactly that
defect in its own manifest, and `scripts/check-dsh-version.mjs` now fails closed
if the field is missing, unbounded, or disagrees with the peer range.

## Breaking changes

**DSH `0.1.7` is no longer supported.** On `0.1.7-rc.2` or earlier, stay on
`0.4.0` — `0.5.0` is skipped at startup with a peer diagnostic rather than loaded
into a half-broken state.

Configuration keys are **unchanged from 0.4.0**: the namespace consolidation and
every rename happened there, so there is nothing to migrate from 0.4.0.

## What changed

- **Moved to the DSH `0.2` line.** For the `0.1.7 → 0.2.0` step the declaration
  was the whole adaptation: every seam this plugin reads — the tools
  `pre-execute` hook, the settings service and its schema, the approval panel and
  its slot contract, the plugin-manager config slot, the ui-settings config form,
  the settings-form model and `Switch`, the frozen client module table, the
  command service and the locale settings — is byte-identical between those tags.
- **The diff headline broke on DSH 0.2.2, and is fixed.** 0.2.2 wrapped the panel
  headline in a `.heading` flex row (`align-items: center; flex-wrap: wrap`), and
  every selector here was positional, so the rebuild injected its per-line rows
  into that wrapper: the rows laid out side by side and wrapped instead of
  stacking. The headline is now located by content — the element owning the first
  text node that carries the diff's line breaks — so a further wrapper cannot
  break it again.
- **The diff font is back at 13px monospace.** The same restructuring had left the
  font rule on an ancestor, where the panel's own `.headline` rule (15px / 24px)
  won, since a direct rule beats an inherited one. It now targets a marker class
  on the headline element itself.
- **`cordis` 4.1.0 and `schemastery` 3.19.0.** Pinning the previous pair left a
  nested `schemastery` under every harness package, and two copies of one schema
  library are two `Schema` types — declaration emit failed with `TS2883`.
  Aligning both deduped it to a single copy.
- **The version checker measures the same window as the gate.** It used to
  classify releases by tuple, so it reported `0.2.2-rc.2` as *above* the declared
  window while the gate admitted it; a guard disagreeing with the thing it guards
  is worse than no guard.

## Verification

Against the real `0.2.2-rc.2` packages:

- `npm run typecheck` — clean on both compilation surfaces.
- **155 tests** across 12 suites, including a locator spec for both panel shapes
  and a stylesheet spec that pins the diff font to the headline element.
- **33 verify-host checks** driving the **built** host artifact on a real cordis
  Context, with its settings double anchored to the real `SettingsForms`
  prototype in both directions.
- Build smoke checks — the client bundle inlines no `node_modules` input and
  requires only the platform module table.
- The published tarball was downloaded back and its contents confirmed.

Known boundaries are unchanged from 0.4.0: command copy is English-only, the
configuration panel needs a loopback page, and the approval panel DOM remains an
unsanctioned coupling — now anchored on content instead of position, which is what
this release's fix changed.

## Upgrade

```sh
# on DSH 0.2.x
dsh plugin --profile web add dsh-edit-approval
# restart `dsh web` (`--profile web`)
```

Already on 0.4.0 and DSH 0.2.x? Update and nothing else changes — this release
does not touch the configuration surface.

# 0.5.0 — 适配 DSH `0.2` 线

`dsh-edit-approval@0.5.0` 发布说明。

---

## 兼容范围 —— 请先读这一节

| | |
| --- | --- |
| **支持的 DSH 范围** | **`0.2` 这一条线** —— `>=0.2.0-rc.1 <0.3.0` |
| 验证目标 | `@deepseek-ai/*@0.2.2-rc.2`，也是 `devDependencies` 精确钉住的版本 |
| 声明方式 | 同一个有上界的 `^0.2.0-rc.1`，写在每个 `@deepseek-ai/dsh-*` peer **以及** `engines.dsh` |
| 上一条线 | `0.1.7` —— **已放弃**，启动时被拒绝并给出诊断 |
| cordis / schemastery | `^4.1.0` / `^3.19.0` |
| Node.js | `^22.19.0 \|\| >=24.0.0` |

所有已发布的 `0.2.x`（含预发布）都放行；`0.1.7-rc.2` 与 `0.3.0-rc.1` 被拒绝。两端都是调用 harness 自己的 `evaluatePluginCompatibility` **实测**得出，不是从范围推断的。

**`engines.dsh` 必须保留 `^`。** 自 DSH 0.2.2 起，准入门读取自带的 `engines.dsh` 并**忽略所有 peer**，所以那里若只写 `>=` 下界，`0.3.0` 及其以上都会被静默放行。本次发布正是修掉了自家 manifest 里的这个缺陷，并且 `scripts/check-dsh-version.mjs` 现在会在该字段缺失、无上界或与 peer 范围不一致时 fail closed。

## 破坏性变更

**不再支持 DSH `0.1.7`。** 若你在 `0.1.7-rc.2` 或更早，请留在 `0.4.0`——`0.5.0` 会在启动时被跳过并给出 peer 诊断，而不是加载成半坏状态。

配置键**与 0.4.0 完全相同**：命名空间合并与所有改名都发生在 0.4.0，因此从 0.4.0 升级无需迁移。

## 本次变更

- **迁移到 DSH `0.2` 线。** 对 `0.1.7 → 0.2.0` 这一步而言，改声明就是全部适配：本插件读取的每个 seam——工具的 `pre-execute` 钩子、设置服务与其 schema、审批面板与其槽契约、plugin-manager 配置槽、ui-settings 配置表单、settings-form model 与 `Switch`、冻结的客户端模块表、命令服务、locale 设置——在这两个 tag 之间**逐字相同**。
- **diff headline 在 DSH 0.2.2 上坏了，已修复。** 0.2.2 把面板 headline 包进了一个 `.heading` flex 行（`align-items: center; flex-wrap: wrap`），而这里的每个选择器都是按位置的，于是重建把逐行 `<div>` 注入了那个容器：行被横向排列并折行，而不是堆叠。现在改为**按内容定位** headline——拥有第一个承载 diff 换行文本节点的元素——再包一层也不会坏。
- **diff 字体回到 13px 等宽。** 同一次重构把字体规则留在了祖先元素上，而面板自身的 `.headline` 规则（15px / 24px）赢了——元素上的直接规则压过继承值。现在作用在 headline 元素自己的标记类上。
- **`cordis` 4.1.0 与 `schemastery` 3.19.0。** 钉旧版会让每个 harness 包下多一份嵌套的 `schemastery`，而同一个 schema 库的两份副本就是两个 `Schema` 类型——声明生成会以 `TS2883` 失败。对齐后去重为单份。
- **版本检查脚本与门禁改为同一套判定。** 它原本按元组分类，于是把 `0.2.2-rc.2` 判为"高于声明窗口"、而门禁实际放行——守卫与它守的东西不一致，比没有守卫更糟。

## 验证

针对真实的 `0.2.2-rc.2` 包：

- `npm run typecheck` —— 两套编译面零错误。
- 12 个套件、**155 项测试**，含两种面板形状的定位器规格，以及把 diff 字体钉到 headline 元素上的样式表规格。
- **33 项 verify-host 检查**，在真实 cordis Context 上驱动**已构建**的 host 产物，其 settings 替身双向锚定真实的 `SettingsForms` 原型。
- 构建冒烟检查——客户端产物不内联任何 `node_modules` 输入，且只 require 平台模块表内的模块。
- 把**已发布**的 tarball 下载回来核对了内容。

已知边界与 0.4.0 相同：命令文案仅英文、配置面板需要 loopback 页面、审批面板 DOM 仍是非契约耦合——只是现在锚定内容而非位置，这也正是本次修复改变的地方。

## 升级

```sh
# 在 DSH 0.2.x 上
dsh plugin --profile web add dsh-edit-approval
# 重启 `dsh web`（`--profile web`）
```

已经在 0.4.0 且 DSH 是 0.2.x？更新即可，其他都不用动——本次发布不触及配置面。
